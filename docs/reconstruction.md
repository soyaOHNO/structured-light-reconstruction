# 撮影画像からの三次元復元 手順書

## 1. この文書について

撮影済みの画像から、対応点の復元・三角測量・精度評価までを行う手順です。暗室での作業が終わり、データが揃った後に読むことを想定しています。

役割分担は次のとおりです。

| 文書 | 扱う範囲 |
| --- | --- |
| [measurement.md](measurement.md) | 機材の配置、光学条件の調整、キャリブレーション、撮影 |
| この文書 | デコード、三角測量、精度評価 |
| [README.md](../README.md) | プロジェクトの目的、ディレクトリ構成、コマンド一覧と実行例（出力つき） |

この文書で扱う処理はすべて撮影済みのデータに対して行うので、**機材がなくても実行できます。** 設定を変えて何度でもやり直せます。

前提として、[measurement.md](measurement.md) の手順で次が揃っていることとします。

- `data/raw/<実験名>/` に 46 枚の撮影画像
- `data/results/<校正の実験名>/calibration.json` にキャリブレーション結果
- 撮影と校正のあいだでカメラ・プロジェクタが動いていないこと

## 2. 処理の流れ

```
撮影画像（46 枚）
     │
[3] デコード ─→ proj_x.npy / proj_y.npy  カメラ画素 ↔ プロジェクタ画素の対応
     │              preview_x.png        ここで目視確認
     │
[4] 三角測量 ─→ points.ply               点群（mm 単位、カメラ原点）
     │   ↑        depth.png              ここで目視確認
     │   └── calibration.json
     │
[5] 精度評価 ─→ evaluation_*.json        既知形状からのずれ
                 residual_*.png           ここで系統誤差の有無を確認
```

各段階に目視確認の材料があります。**次へ進む前に必ず見てください。** 数値だけでは、もっともらしく間違った結果を見逃します。

## 3. デコード

撮影画像から、カメラ画素ごとのプロジェクタ座標を復元します。

```powershell
uv run --no-sync python scripts/03_decode.py <実験名>


# 実行例（2026-09-25）
uv run --no-sync python scripts/03_decode.py test04
```

`data/results/<実験名>/` に次が出力されます。

| ファイル | 内容 |
| --- | --- |
| `proj_x.npy` / `proj_y.npy` | カメラ画素ごとのプロジェクタ座標（無効画素は -1） |
| `mask.png` | 最終的な有効画素 |
| `shadow_mask.png` | 全白・全黒の差から作った影のマスク |
| `preview_x.png` / `preview_y.png` | 目視確認用のカラー画像 |

### 3.1 結果の確認

**`preview_x.png` が左から右へ、`preview_y.png` が上から下へ滑らかに変化していれば成功です。** 対象物の表面でグラデーションが曲がっているのが奥行きの情報です。まだら模様やノイズだらけの場合は、露光か `[decode]` の設定に問題があります。

有効画素の割合も表示されます。投影範囲が画面の一部であったり、影の領域があれば数十パーセントになるのが普通です。

`mask.png` と `shadow_mask.png` を見比べると、どの段階で画素が落ちているかが分かります。影マスクは通っているのに最終マスクで落ちている画素は、ビットの判定に失敗しています（3.2 を参照）。

### 3.2 細かいビットの扱い

`--bits` を付けると、縞幅ごとの判定成功率が表示されます。

```powershell
uv run --no-sync python scripts/03_decode.py <実験名> --bits

# 実行例（2026-09-25）
uv run --no-sync python scripts/03_decode.py test04 --bits
```

実測例です。

```
縞幅 8 投影画素以上 : 84〜100%
縞幅 4 投影画素     : 78%
縞幅 2 投影画素     : 51%
縞幅 1 投影画素     : 10%   ← ぼけて潰れている
```

グレイコードは全ビットが揃わないと座標が決まらないため、解像できないビットを使うと大量の画素が捨てられます。**通過率が急に落ちる本数を `skip_fine_bits` に設定してください。** そのビットを使わずにデコードします。

| `skip_fine_bits` | 分解能 | 有効画素率（実測） |
| --- | --- | --- |
| 0 | 1 投影画素 | 0.2% |
| 1 | 2 投影画素 | 9.7% |
| 2 | 4 投影画素 | 40.0% |
| 3 | 8 投影画素 | 58.7% |

現在は **2** を使っています。ピントを追い込めれば下げられます。**撮影し直す必要はありません。** 同じ画像を設定だけ変えてデコードし直せます。

### 3.3 しきい値

`[decode]` には 2 つのしきい値があります。

**`mask_threshold`** は、全白と全黒の輝度差がフルスケールのこの割合を下回る画素を、影または投影範囲外として除外します。

**`bit_threshold`** は、パターンと反転パターンの輝度差がこれを下回るビットを判定不能とします。**その画素自身の振れ幅（全白と全黒の差）に対する比**であって、絶対値ではありません。相対値にすることで、対象の反射率、レンズ周辺の減光、Bayer 配列の色ごとの感度差を吸収できます。

実際、絶対値で判定していたときは Bayer の位相によって有効率が偏り（赤 39.8% / 緑 30.6%）、プレビューに規則的な格子模様が出ていました。相対値に変えたところ 41.1% / 45.3% まで揃い、模様が消えました。

## 4. 三次元復元

```powershell
uv run --no-sync python scripts/06_reconstruct.py <実験名> --calibration <校正の実験名>

# 実行例（2026-09-25）
uv run --no-sync python scripts/06_reconstruct.py test04 --calibration calib01
```

`data/results/<実験名>/` に出力されます。

| ファイル | 内容 |
| --- | --- |
| `points.ply` | 点群（色付き）。点群ビューアで開きます（4.4 を参照） |
| `points.npy` | 同じ点群の numpy 配列（mm 単位、カメラ原点） |
| `pixels.npy` | 各点がどのカメラ画素から来たか。精度評価の範囲指定に使う |
| `errors.npy` | 各点の再投影誤差 |
| `colors.npy` | 各点の色。描画に使う |
| `depth.png` | 奥行きを色で表した確認用画像 |
| `reconstruct.json` | 点数、奥行き範囲、再投影誤差 |

### 4.1 原理

デコードで「カメラのこの画素は、プロジェクタのこの画素から照らされていた」という対応が得られています。キャリブレーションからは、その 2 つの画素がそれぞれ空間のどの向きの光線に対応するかが分かります。**2 本の光線の交点が対象物の表面です。**

プロジェクタは単一の光学中心を持つ中心投影装置なので、画素が 1 本の光線を定めます。これにより、ステレオカメラと同じ三角測量がそのまま使えます（プロジェクタを逆向きのカメラとして扱う定式化）。

座標系はカメラを原点とし、単位は mm です。キャリブレーションでチェッカーボードの実寸を mm で与えているため、復元結果も実スケールになります。

### 4.2 結果の確認

まず `depth.png` を開きます。**手前のものが青、奥のものが赤で表示されます。** 対象物と背景が奥行きで分離できていれば、ひとまず成功です。形そのものの確認は 4.3 で行います。

### 4.3 形状を目で確認する

`depth.png` は色で奥行きを表しているだけなので、形そのものは分かりません。**視点を変えて見ないと、立体として正しいかは判断できません。**

方法は 2 つあります。

**(a) 描画スクリプトを使う（インストール不要）**

```powershell
uv run --no-sync python scripts/08_render.py <実験名>

# 実行例（2026-09-25）
uv run --no-sync python scripts/08_render.py test04
```

視点を変えた静止画 6 枚（`views/`）と、視点を左右に振ったアニメーション（`turntable.gif`）を作ります。

```powershell
start data\results\<実験名>\turntable.gif
```

**まず GIF を見てください。** 静止画では奥行きが分かりにくいのに対し、視点が動くと立体かどうかが一目で分かります。手前のものが奥のものより大きく動いて見えれば、正しく立体になっています。静止画のほうは発表資料にそのまま使えます。

`--color depth` を付けると奥行きによる着色（手前が青、奥が赤）になり、表面の起伏が見やすくなります。実際の色だと模様と起伏が混ざって分かりにくい場合に使ってください。

この描画は numpy だけで行っており、対話的な操作はできません。じっくり観察したい場合は (b) を使ってください。

**(b) 点群ビューアで開く**

`points.ply` は標準的な PLY 形式（バイナリ）なので、点群ビューアで開けます。[CloudCompare](https://www.cloudcompare.org/)（無料）が点群向けでは扱いやすく、距離や角度を測る機能もあります。MeshLab でも開けます。

**どちらもこの PC には入っていません。** 対話的に回して見たい場合や、断面を取って寸法を測りたい場合はインストールしてください。

### 4.4 外れ値の除去

2 段階で落としています。

1. **奥行きの範囲**（`min_depth_mm` 〜 `max_depth_mm`）— デコードの誤りは、極端に近い／遠い点として現れることが多い
2. **再投影誤差**（`max_reprojection_error_px`）— 三角測量した点を両方の像に投影し直し、元の画素から離れていた点を捨てる。2 本の光線がきれいに交わらなかった点、つまり対応を誤った画素が落ちます

実測では有効画素の 47.2% が残りました。**残る割合が極端に低い場合は、校正と計測のあいだで機材が動いた可能性を疑ってください。** 機材が動くと光線が交わらなくなり、再投影誤差で軒並み落ちます。

## 5. 精度評価

復元結果は見た目がもっともらしくても、誤差の大きさは分かりません。**形が分かっているものを計測し、その形からのずれを測って初めて精度が数値になります。**

```powershell
uv run --no-sync python scripts/07_evaluate.py <実験名> --shape plane


# 実行例（2026-09-25）
uv run --no-sync python scripts/07_evaluate.py test04 --shape plane
```

### 5.1 平面と球の使い分け

**平面**は最も手軽で、残差の広がりがそのまま奥行き方向のノイズの大きさになります。壁、平らな板、定盤などが使えます。

**球**は直径の実測値と比較することで、**スケールの系統誤差**が見えます。平面では検出できない種類の誤差です。スケールのずれはチェッカーボードの `square_size_mm` の設定誤りから生じるので、球で直径が合わなければ、まずそこを疑います。

```powershell
uv run --no-sync python scripts/07_evaluate.py <実験名> --shape sphere --diameter 50.0

# 実行例（2026-09-25）
uv run --no-sync python scripts/07_evaluate.py test04 --shape sphere --diameter 50.0
```

両方を測ると、**ばらつき（ノイズ）と偏り（系統誤差）という性質の違う誤差を切り分けられます。**

### 5.2 評価する範囲の指定

対象物以外のものが写っている場合は、`--roi` で画面上の矩形を指定します。`depth.png` を見ながら位置を読み取ってください。

```powershell
uv run --no-sync python scripts/07_evaluate.py <実験名> --shape plane --roi 0,0,550,1200

# 実行例（2026-09-25）
uv run --no-sync python scripts/07_evaluate.py test04 --shape plane --roi 0,0,550,1200
```

指定は `x,y,幅,高さ` の順で、カメラ画像の画素座標です。省略すると点群全体を使います。

範囲に多少ほかのものが混ざっても、当てはめには RANSAC を使っているので少数派として除外されます。ただし混入が半分近くになると、そちらが選ばれてしまうことがあります。`--threshold` で外れ値とみなす距離（既定 2.0 mm）を調整できます。

### 5.3 結果の読み方

```
形状からのずれ（内点のみ）:
  RMS         : 0.380 mm
  平均絶対誤差: 0.320 mm
  最大         : 1.935 mm
  内点の割合   : 100.0%（156,059 / 156,059 点）
```

**RMS が計測精度の指標です。** 平面を測った場合、これが奥行き方向のノイズの標準偏差にあたります。

**内点の割合**が低い場合は、範囲に別のものが混ざっているか、`--threshold` が厳しすぎます。

**最大値が RMS の 5 倍を大きく超える**場合は、少数の外れ値が残っています。三角測量の再投影誤差の上限（`max_reprojection_error_px`）を下げると減ります。

### 5.4 残差の画像

`residual_<形状>.png` は、残差を色で表した画像です。**青が手前側へのずれ、白がずれなし、赤が奥側へのずれ**です。

**一様なノイズに見えれば正常です。** 縞模様や勾配が見える場合は系統誤差で、原因が別にあります。

| 残差の見え方 | 疑うべき原因 |
| --- | --- |
| 一様なノイズ | 正常。RMS がそのまま精度 |
| 縦または横の縞 | グレイコードの縞の境界。`skip_fine_bits` を上げるか位相シフトを導入 |
| 画面の端ほど大きい勾配 | レンズ歪みの推定不足。ボードを画面の四隅にも配置して校正し直す |
| 一方向へ滑らかに増える偏り | 平面そのものが歪んでいる（板のたわみ）か、スケール誤差 |

### 5.5 記録

結果は `evaluation_<形状>.json` に保存されます。`--note` で条件をメモに残せます。距離や角度を変えて複数回測るときに、後から比較できます。

```powershell
uv run --no-sync python scripts/07_evaluate.py <実験名> --shape plane --note "距離 700mm、正対"

# 実行例（2026-09-25）
uv run --no-sync python scripts/07_evaluate.py test04 --shape plane --note "距離 700mm、正対"
```

## 6. うまくいかないときの切り分け

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| プレビューが規則的な格子状に欠ける | 細かい縞が解像できていない | `--bits` で通過率を見て `skip_fine_bits` を上げる |
| 有効画素が極端に少ない | 露光過多で飽和、または露光不足 | 全白画像の最大値を確認し、露光を直して撮り直す |
| プレビューがまだら模様 | 対象が光沢を持ち、鏡面反射で対応が取れていない | 対象を替えるか、露光を下げる |
| 復元した点がほとんど残らない | 校正後に機材が動いた | 校正からやり直す |
| 復元した平面が曲がっている | レンズ歪みの推定不足 | ボードを画面の四隅にも配置して校正し直す |
| 球の直径が実測値と合わない | スケールの系統誤差 | チェッカーボードの `square_size_mm` を実測し直す |
| 残差に縞が見える | グレイコードの縞の境界 | `skip_fine_bits` を上げる。または位相シフトを導入 |
| `pixels.npy` がないと言われる | 古い形式で保存された点群 | `06_reconstruct.py` を実行し直す |

撮影・校正の段階の問題は [measurement.md](measurement.md) を参照してください。

## 7. 精度を上げるには

現状の制約と改善の候補です。**(処理)** は設定を変えて撮影データをそのまま使えるもの、**(撮影)** は撮り直しが必要なものです。

**(処理) 細かいビットが使えていない。** `skip_fine_bits = 2` なので、プロジェクタ座標の分解能は 4 投影画素です。ピントを追い込めば下げられます。まず現在のデータで 1 や 0 を試し、有効画素率がどこまで落ちるか見てください。

**(撮影+処理) グレイコードの縞の境界で点が抜ける。** 縞の境目にかかった画素はどちらとも判定できないため、二値グレイコードでは原理的に残ります。位相シフトパターンを併用すると解消し、サブピクセル精度になります。パターン生成・撮影・デコードの全段に手を入れる必要があります。

**(撮影) チェッカーボードが小さい。** 現在のボードは 70 × 40 mm で、カメラ画面の 3 割程度しか占めていません。A4 いっぱい（1 マス 25〜30 mm）にすると交点の位置精度が上がり、校正精度が上がります。

**(撮影) カメラがプロジェクタ画像の一部しか見ていない。** 横 40%・縦 49% のため、プロジェクタの内部パラメータの推定が不安定になりがちです。校正のときだけでもボードを画面の四隅まで動かすと改善します。

**(撮影) 光沢のある対象物への対応。** 飽和を避けるために露光を下げると暗部が沈みます。露光を変えた複数枚を合成する HDR 撮影を導入すると、明暗差の大きい対象を扱えます。

### この段階で判明した問題と対処

- 縞幅 1〜2 投影画素のビットが解像できず、`skip_fine_bits` を導入。有効画素が 31.6% → 40.0% に改善
- ビット判定のしきい値を絶対値から画素ごとの相対値へ変更。Bayer 配列の色による偏り（赤 39.8% / 緑 30.6%）が解消し、プレビューの格子模様が消えた
- `cv2.COLORMAP_COOLWARM` が OpenCV 5.0 に存在せず、残差表示用の発散配色を自前で用意した
