# 構造化光による三次元計測 手順書

## 1. この文書について

暗室での機材設置から三次元点群の出力までの手順をまとめたものです。実際に計測を行う人が、この文書を順に追えば一連の作業を再現できることを目指しています。

役割分担は次のとおりです。

| 文書 | 扱う範囲 |
| --- | --- |
| [setup/setup.md](../setup/setup.md) | Windows での環境構築、SDK の導入、機器の初期動作確認 |
| [README.md](../README.md) | プロジェクトの目的、ディレクトリ構成、コマンド一覧と実行例（出力つき） |
| この文書 | 暗室での計測手順、光学条件の決め方、失敗の切り分け |
| [reconstruction.md](reconstruction.md) | デコード、三角測量、精度評価 |

環境構築が済んでいることを前提とします。コマンドはすべてプロジェクトのルートディレクトリで実行します。

この文書は撮影が終わるところまでを扱います。撮影後の処理は [reconstruction.md](reconstruction.md) へ続きます。

## 2. 計測の流れ

```
[準備]  パターン生成 ── 一度だけ。投影解像度を変えたら再生成
           │
[調整]  ピント・絞り・露光を決める
           │
        試し撮り 1 回 ─→ デコード設定（skip_fine_bits）を決める
           │
[校正]  ボードを姿勢ごとに撮影 ─→ キャリブレーション ─→ calibration.json
           │                                                    │
           │  ← ここから先、カメラとプロジェクタは動かさない →   │
           │                                                    │
[計測]  対象物にパターン投影・撮影 ─→ デコード ─→ 三角測量 ──┴─→ 点群
```

キャリブレーションを先に済ませます。校正と計測のあいだで機材が動くと校正結果が無効になるため、**校正してから対象物だけを入れ替えて計測する**のが安全な順序です。対象物を撮ってから校正すると、そのあいだに機材に触れてしまう危険があります。

校正と計測のあいだでカメラ・プロジェクタを動かしてはいけません。両者の位置関係を使って三角測量するため、動かすと校正結果が無効になります。対象物だけを入れ替えます。

## 3. 機材の配置

### 3.1 満たすべき条件

**投影範囲とカメラの視野が重なっていること。** 対象物の計測したい面に投影光が当たり、かつその面がカメラに写っている必要があります。どちらか一方でも欠けている画素は復元できません。

**カメラとプロジェクタに十分な角度をつけること。** 2 本の光線の交点として奥行きを求めるので、光軸が平行に近いと交点の位置が定まらず、奥行き精度が落ちます。一方で角度が大きいほど、プロジェクタから見えてカメラから見えない（またはその逆の）影の領域が増えます。30〜45 度程度が目安です。

**対象物までの距離を、校正時と計測時で揃えること。** レンズのピントは特定の距離にしか合いません。

**台形補正を切ること。** プロジェクタ側の台形補正やオートフォーカスが働くと、投影される画素の位置が変わってしまい、校正結果と食い違います。

### 3.2 実際の配置（2026-09-25 時点）

校正結果から逆算した実測値です。

| 項目 | 値 |
| --- | --- |
| カメラとプロジェクタの距離（基線長） | 688 mm |
| 光軸のなす角 | 43.1 度 |
| 対象物までの距離 | 約 590〜750 mm |
| 計測できた領域 | 274 mm × 191 mm |
| プロジェクタの水平画角 | 42.6 度（スローレシオ 1.28） |

カメラの視野はプロジェクタの投影範囲より狭く、投影画像の横 40%・縦 49% だけを見ています。これは計測自体には支障ありませんが、プロジェクタの内部パラメータの推定には不利です（[11 節](#11-精度を上げるには)を参照）。

## 4. 事前準備

### 4.1 カメラを他のアプリから解放する

**SpinView を終了してください。** カメラは同時に 1 つのアプリケーションからしか開けません。SpinView が起動したままだと、スクリプトは「カメラが 0 台」または初期化エラーで止まります。

### 4.2 環境を確認する

```powershell
uv run --no-sync python scripts/00_check_hardware.py
```

カメラの型番・シリアル番号、設定値、撮影テストの結果が表示され、続いてプロジェクタに全白・全黒・パターンが順に表示されれば正常です。

`PySpin` が見つからないというエラーが出た場合は、wheel が消えています。`uv sync`（`--inexact` なし）を実行すると PySpin がアンインストールされるので、README の手順で入れ直してください。

### 4.3 投影パターンを生成する

初回のみ必要です。投影解像度を変えたときは `--force` を付けて作り直します。

```powershell
uv run --no-sync python scripts/01_generate_patterns.py
```

1920 × 1080 の場合、グレイコード 44 枚と全白・全黒の計 46 枚が `data/patterns/1920x1080/` に生成されます。パターンは解像度ごとのディレクトリに入るので、解像度を取り違えて投影することはありません。

## 5. 光学条件の調整

**この節が計測全体の成否を決めます。** 後段のデコードは「投影した明るさと撮影された明るさが比例している」ことを前提にしているため、ここで条件を外すと、原因の分かりにくい失敗になります。

### 5.1 ピントと絞り

プロジェクタと カメラの両方のピントを、対象物のある距離に合わせます。

グレイコードは縞を細かくしていくことで座標を絞り込みますが、**縞幅が光学系の分解能を下回ると、ぼけて潰れて判定できなくなります。** ピントが甘いほど、使えるビットが減り、分解能が落ちます。

カメラの絞りは、被写界深度と明るさのトレードオフです。対象物に奥行きがある場合は絞ったほうが全体にピントが合いますが、そのぶん露光を長くする必要があります。

### 5.2 露光とゲイン

**ゲインは 0 dB のままにします。** ゲインを上げるとノイズが増え、細かい縞の判定が不安定になります。明るさは露光時間で調整します。

露光時間は [config/default.toml](../config/default.toml) の `exposure_time_us` で設定します。決め方は次のとおりです。

1. 仮の値で対象物を 1 回撮影する
2. 全白画像の明るさを確認する
3. 飽和していれば下げ、暗すぎれば上げる

```powershell
uv run --no-sync python -c "import cv2; a=cv2.imread('data/raw/<実験名>/white.png', cv2.IMREAD_UNCHANGED); print('最大', a.max(), '/ 平均', round(float(a.mean()),1), '/ 飽和画素数', int((a>=65000).sum()))"
```

**飽和は特に避けてください。** 飽和した画素はパターンと反転パターンの差が出なくなるため、その領域は丸ごとデコードできません。目安は最大値が 50000〜60000 程度（フルスケール 65535）です。

実際の作業では、当初 50000 µs で撮影して飽和が目立ったため、最終的に **5000 µs** に落ち着きました。

### 5.3 自動制御はすべて切る

自動露光・自動ゲイン・自動ホワイトバランスは [src/slr/camera.py](../src/slr/camera.py) が明示的に無効化します。パターンごとに明るさが変わると、パターン間の比較が成立しなくなるためです。ガンマも 1.0 に固定します。ガンマ補正は輝度の線形性を壊します。

SpinView で設定を変更した場合、その設定がカメラに残ることがありますが、スクリプトが起動時に上書きするので気にする必要はありません。起動時に実際の設定値が表示されるので、そこで確認してください。

### 5.4 試し撮りでデコード設定を決める

キャリブレーションのスクリプトは内部でグレイコードのデコードを行うため、**デコードの設定を校正より先に決めておく必要があります。**

対象物（または壁など）を 1 回撮影し、デコードして `skip_fine_bits` を決めてください。判断の仕方は [reconstruction.md の 3.2](reconstruction.md#32-細かいビットの扱い) にまとめています。

```powershell
uv run --no-sync python scripts/02_capture.py trial
uv run --no-sync python scripts/03_decode.py trial --bits
```

この試し撮りは設定を決めるためだけのものなので、結果は捨てて構いません。光学系（ピント・絞り・距離）を変えたら決め直してください。

## 6. キャリブレーション

カメラとプロジェクタの内部パラメータ（焦点距離、主点、レンズ歪み）と、両者の相対姿勢を求めます。

**前提**: [5 節](#5-光学条件の調整)の光学条件の調整と、`skip_fine_bits` の決定が済んでいること。校正スクリプトは内部でデコードを行うため、デコードが成立しない設定のままでは校正もできません。

**この節以降、カメラとプロジェクタを動かしてはいけません。** 動かした場合は校正からやり直しです。

### 6.1 チェッカーボードの準備

**`columns` と `rows` に設定するのは「内側の交点の数」で、マスの数ではありません。** マスが 9 × 6 のボードなら交点は 8 × 5 です。ここを間違えると検出に必ず失敗します。

`square_size_mm` には 1 マスの一辺を定規で実測した値を入れてください。**この値が復元結果のスケールを決めます。**

**ボードは無光沢の紙に印刷し、平らな板に貼ってください。** 光沢紙やラミネートは避けます（理由は 6.2）。たわむと精度が出ません。

分からない場合は、1 姿勢だけ撮影してから実測できます。

```powershell
uv run --no-sync python scripts/05_calibrate.py <実験名> --probe

# 実行例（2026-09-25）
uv run --no-sync python scripts/05_calibrate.py calib01 --probe
```

### 6.2 撮影

```powershell
uv run --no-sync python scripts/04_capture_calibration.py <実験名> --poses 12

# 実行例（2026-09-25）
uv run --no-sync python scripts/04_capture_calibration.py calib01 --poses 12
```

**1 姿勢につき 2 段階で撮影します。スクリプトが指示を出します。**

1. **部屋の照明を点けて 1 枚**（プロジェクタは黒を表示）— 交点検出用
2. **部屋の照明を消してパターン一式**（暗室）— プロジェクタ座標の取得用

照明を分けるのは、**プロジェクタの光をボードに当てると微細な鏡面反射が起きて、白マスと黒マスの区別がつかなくなる**ためです。実際に光沢のあるボードで試したところ、黒マスの内部の輝度のばらつきが標準偏差 47（平均 72 に対して）に達し、壁の標準偏差 1.4 と比べて桁違いでした。さらに投影光の偏りによって盤面の右側では黒マスが白マスより明るくなり、どの検出器でも対応できない状態でした。部屋の拡散光ならこれを避けられます。

交点の検出はパターン撮影の前に行うので、失敗しても数秒で分かります。検出できない場合は露光を変えて自動的に撮り直し（既定 4 回まで）、それでも駄目なら画像を `data/raw/<実験名>/failed/` に保存し、どの交点数なら検出できたかを表示します。

撮影のコツです。

- 姿勢ごとに**傾き・距離・画面内の位置を変える**。似た姿勢ばかりだと精度が出ません
- ボード全体がカメラの画面内に収まっていること
- **画面内で大きく写す**ほうが交点の位置精度が上がります
- 画面の四隅にも配置すると、レンズ歪みの推定が安定します
- 10〜12 姿勢が目安です（最低 8 姿勢）

途中で終了した場合、同じ実験名で再実行すると続きから再開します。不完全な姿勢は起動時に自動で削除されます。

### 6.3 校正の実行

```powershell
uv run --no-sync python scripts/05_calibrate.py <実験名>


# 実行例（2026-09-25）
uv run --no-sync python scripts/05_calibrate.py calib01
```

結果は `data/results/<実験名>/calibration.json` に保存されます。

**再投影誤差が 1.0 画素未満であれば十分です。** 大きい場合は、ボードのたわみ、姿勢のばらつき不足、`square_size_mm` の設定ずれを疑ってください。

### 6.4 結果の検算

校正結果が妥当かどうかは、物理的に分かっている値と突き合わせると確認できます。

**カメラの焦点距離**を実寸に直します。BFS-U3-23S3C（Sony IMX392）の画素ピッチは 3.45 µm です。

```
4681.4 px × 3.45 µm = 16.15 mm   → 実際のレンズは 16 mm（誤差 1%）
```

**プロジェクタの主点**が画像の外に出ているのは正常です。実測値は縦 1213 で画像高 1080 を超えていますが、プロジェクタは光軸より上（または下）だけに投影するレンズシフトを持つため、これで正しい姿です。

**基線長**が実際の機材間距離とおおむね合っているかも確認してください。

## 7. 計測対象の撮影

**前提**: [6 節](#6-キャリブレーション)の校正が済んでいて、それ以降カメラとプロジェクタを動かしていないこと。

部屋の照明を消し、対象物を配置して実行します。対象物だけを入れ替え、機材には触れません。

```powershell
uv run --no-sync python scripts/02_capture.py <実験名>

# 実行例（2026-09-25）
uv run --no-sync python scripts/02_capture.py test04
```

`<実験名>` が `data/raw/` 以下の保存先の名前になります。**実験ごとに別の名前を付けてください。** 既存の名前を指定するとエラーで止まります（条件の違う画像が混ざるのを防ぐため）。

46 枚の撮影に約 1 分かかります。その間は機材にも部屋の明るさにも触れないでください。中断したいときは `Esc` です。

撮影条件は `metadata.json` として一緒に保存されます。後から「どの露光で撮ったか」を画像だけから復元するのは困難なので、必ず残ります。

### 撮影がずれない仕組み

パターンを切り替えてすぐ撮影すると、バッファに残った古いフレームを掴んで、**投影パターンと撮影画像が 1 枚ずれます。** この不具合は結果を見ても気づきにくく、原因の特定が困難です。

対策として 2 つを入れています。ストリームバッファを `NewestOnly` にして古いフレームを破棄することと、パターン表示後に `warmup_sec`（既定 1.0 秒）待ってから撮影することです。どちらも [config/default.toml](../config/default.toml) で設定します。プロジェクタの応答が遅い場合は待機時間を伸ばしてください。

## 8. うまくいかないときの切り分け

撮影・校正の段階で実際に遭遇した失敗と、その見分け方です。デコード以降の問題は [reconstruction.md](reconstruction.md) を参照してください。

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| カメラが 0 台と表示される | SpinView が起動している | SpinView を終了する |
| `PySpin` が import できない | `uv sync` が wheel を削除した | `uv sync --inexact` を使い、wheel を入れ直す |
| 有効画素が極端に少ない | 露光過多で飽和、または露光不足 | 全白画像の最大値を確認して露光を調整する |
| 投影パターンと撮影画像が 1 枚ずれている | バッファの古いフレームを取得している | `buffer_handling = "NewestOnly"` と `warmup_sec` を確認する |
| チェッカーボードの交点が検出できない | 交点数の設定がマス数になっている | 交点数（マス数 − 1）に直す。`--probe` で実測できる |
| 同上（設定は正しいのに検出できない） | ボードの鏡面反射、または露光不足 | 部屋の照明で撮る方式になっているか確認する。無光沢のボードにする |
| 再投影誤差が 1 画素を超える | ボードのたわみ、姿勢のばらつき不足、実寸の設定ずれ | ボードを平らな板に貼り直し、姿勢を増やす |

## 9. 撮影・校正の段階でできる改善

撮り直しが必要な改善の候補です。設定を変えるだけで試せるものは [reconstruction.md](reconstruction.md) にまとめています。

**ピントを追い込む。** 縞幅の細かいビットが解像できれば `skip_fine_bits` を下げられ、分解能と点密度が上がります。現在は 4 投影画素単位です。

**チェッカーボードを大きくする。** 現在のボードは 70 × 40 mm で、カメラ画面の 3 割程度しか占めていません。A4 いっぱい（1 マス 25〜30 mm）にすると交点の位置精度が上がります。

**校正時にボードを画面の四隅まで動かす。** カメラが見ているのはプロジェクタ画像の横 40%・縦 49% だけなので、プロジェクタの内部パラメータの推定が不安定になりがちです。観測範囲を広げると改善します。レンズ歪みの推定にも効きます。

**光沢のある対象物には HDR 撮影を検討する。** 飽和を避けるために露光を下げると暗部が沈みます。露光を変えた複数枚を合成すると、明暗差の大きい対象を扱えます。

## 10. 実施記録

### 2026-09-25 初回の通し計測

すべての工程を通して点群の出力まで到達しました。

**設定**

| 項目 | 値 |
| --- | --- |
| 投影解像度 | 1920 × 1080（パターン 46 枚） |
| 露光時間 | 5000 µs（計測時） / 20000 µs（交点検出時） |
| ゲイン / ガンマ | 0 dB / 1.0 |
| 画素形式 | BayerRG16（RAW） |
| パターン切り替えの待機 | 1.0 秒（撮影 46 枚で 57.5 秒） |
| `skip_fine_bits` | 2（4 投影画素単位） |
| チェッカーボード | 交点 8 × 5、1 マス 10 mm |

**キャリブレーション結果（12 姿勢）**

| 項目 | 値 |
| --- | --- |
| 再投影誤差（カメラ） | 0.2031 画素 |
| 再投影誤差（プロジェクタ） | 0.2351 画素 |
| 再投影誤差（ステレオ） | 0.4643 画素 |
| カメラ焦点距離 | fx 4681.4 / fy 4670.5 画素（実寸 16.15 mm、レンズは 16 mm） |
| プロジェクタ焦点距離 | fx 2464.4 / fy 2482.8 画素 |
| 基線長 | 688 mm |

撮影した石膏像の復元結果と精度評価は [reconstruction.md](reconstruction.md) の実施記録にまとめています。

**この回で判明した問題と対処**

- 当初の露光 50000 µs では飽和が多く、5000 µs へ変更
- 光沢のあるチェッカーボードがプロジェクタ光下で検出不能。部屋の照明で撮る方式へ変更して解決
- チェッカーボードの設定をマス数（9 × 6）で入れていたため検出できず。交点数（8 × 5）へ修正
