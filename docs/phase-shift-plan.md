## 1. 何をするのか

正弦波の縞を投影し、**位相を 1/N 周期ずつずらしながら N 枚撮影**します。各カメラ画素での位相からサブピクセル精度のプロジェクタ座標を求めます。

グレイコードは残します。位相から分かるのは「1 周期のどこにいるか」だけで、**何周期目かはグレイコードで決める**ためです。二段構えになります。

```
グレイコード  → 粗いが絶対的な位置（現在 4 投影画素単位）
位相シフト    → 細かいが 1 周期内でしか分からない位置
両方を合わせる → 絶対的かつサブピクセル
```

## 2. 期待される効果

**1. 分解能が上がる。** 現在はプロジェクタ座標が 4 投影画素単位に量子化されています（`skip_fine_bits = 2`）。位相シフトならサブピクセルになります。

**2. 縞の境界の欠損が消える。** 現在、グレイコードの縞の境目にかかった画素はどちらとも判定できず、残差画像に格子状の抜けとして残っています。位相は連続量なので、この問題自体がなくなります。

**3. 有効画素が増える見込み。** 細かいビットを捨てる必要がなくなるため。現在の有効画素率は 40.0% です。

移植元の procamtools も同じ方式です（`options.ini` の `nfringes=8`）。

## 3. 原理と式

### 投影するパターン

周期 T（投影画素）の正弦波を、位相を 2πn/N ずつずらして N 枚作ります。

```
I_n(x) = 0.5 + 0.5 · cos(2π x / T − 2π n / N)      n = 0 … N−1
```

8bit 画像なので 0〜255 に量子化します。横方向は x、縦方向は y について同じものを作ります。

### 撮影画像から位相を求める

撮影される輝度は次の形になります。A は環境光と反射率、B は縞の振幅です。

```
I'_n = A + B · cos(φ − 2π n / N)
```

N 枚から位相 φ を求めます。

```
S = Σ I'_n · sin(2π n / N)
C = Σ I'_n · cos(2π n / N)

φ = atan2(S, C)          範囲は (−π, π]
```

同時に**変調度**が求まります。これが小さい画素は縞が届いていない（影、飽和、低反射率）ので、信頼できない画素として落とします。

```
B = (2 / N) · √(S² + C²)
```

### 周期内の位置

```
u_frac = ((φ + 2π) mod 2π) / (2π) · T        範囲は [0, T)
```

### グレイコードとつなぐ（位相接続）

グレイコードで求めた粗い座標 `x_gc` から、何周期目か `k` を決めます。

```
k = round((x_gc − u_frac) / T)
x = k · T + u_frac
```

**この接続が成立する条件は `|x_gc − x_true| < T / 2` です。** グレイコードの誤差が周期の半分を超えると、隣の周期に飛んで大きく外れます。

**`data/raw` と `data/results` の構造は変えません。** 1 回の `02_capture.py` で 62 枚すべてを撮ります。グレイコードと正弦波を別々に撮ると、そのあいだに対象物や機材が動く危険があるためです。

### 新しいトップレベルのディレクトリは作らない（決定）

部品は `src/slr/`、実行するものは `scripts/` という境界を保ちます。新しいスクリプトも不要で、`01` `02` `03` がそのまま使えます。

### 設定項目（決定）

```toml
[pattern]
method = "graycode+phase"   # "graycode" で従来どおり
phase_steps = 8             # N

```

`Config.pattern_dir` は `<解像度>_<方式>` として組み立てます。`method = "graycode"` なら `1920x1080_graycode`、`"graycode+phase"` なら `1920x1080_graycode+phase<N>` です。

### manifest の形式（決定）

どの名前がどの役割かを記録します。デコード側が名前で振り分けられるようにするためです。

```json
{
  "method": "graycode+phase",
  "projector_width": 1920,
  "projector_height": 1080,
  "graycode_count": 44,
  "phase_steps": 8,
  "phase_period_px": 16,
  "names": ["pattern_00", ..., "phase_h_00", ..., "white", "black"],
  "roles": {
    "pattern_00": "graycode",
    "phase_h_00": "phase_horizontal",
    "phase_v_00": "phase_vertical",
    "white": "white",
    "black": "black"
  }
}
```

### `proj_x` / `proj_y` を float32 にする（決定）

現在は int32 で、無効画素を `-1`（`decode.INVALID`）で表しています。サブピクセルになるので float32 へ変えます。

無効画素の表し方は **`mask` を正とし、座標側は NaN** にします。`-1` という番兵は、float では比較が不安定になるためです。

影響範囲は次のとおりです。

- `src/slr/decode.py` — `DecodeResult`、`decode_arrays`、`save`
- `src/slr/reconstruct.py` — 内部で float に変換しているので、NaN を除く処理の追加のみ
- `src/slr/calibration.py` — `projector_corners` は `mask` で絞っているので影響は小さい
- `tests/test_decode_roundtrip.py` — 期待値の比較を許容誤差つきに変更

### 位相周期の制約（決定）

**T は、グレイコードの信頼できる分解能の 2 倍以上にします。**

現在 `skip_fine_bits = 2` で分解能は 4 投影画素、グレイコード座標の誤差は最大 ±2 画素です。T = 16 なら T/2 = 8 画素なので、十分な余裕があります。

T を小さくすると位相の精度は上がりますが、周期の特定に失敗する危険が増します。**まず T = 16 で動かし、安定してから小さくする**という順序にしてください。

## 6. 検証の方法

**既存のテストと同じ考え方です。三角測量やデコードは、間違っていてももっともらしい結果が出るので、数値で確かめます。**

### 往復テスト（必須）

`tests/test_decode_roundtrip.py` に追加します。生成した正弦波パターンをそのまま「ノイズのない完全な撮影画像」とみなして復号し、元の画素位置と一致するかを見ます。

- 復号した座標の誤差が 0.05 投影画素未満であること（量子化とグレイコードの接続を含めて）
- 全画素が有効になること
- 位相接続が全画素で正しい周期を選んでいること

### 接続の破綻を検出するテスト

グレイコード側の座標にわざと T/2 を超える誤差を与え、**接続が壊れることを確認**します。壊れ方を知っておくと、実写で同じ症状が出たときに原因が分かります。

### ノイズ耐性

撮影画像にガウスノイズを載せ、位相の誤差がノイズの大きさに対してどう増えるかを測ります。8 枚と 4 枚の比較ができると、枚数の選択に根拠が持てます。

## 7. 落とし穴

### プロジェクタのガンマ（最重要）

**これが最大の新しいリスクです。**

二値のグレイコードでは輝度差の符号しか見ないので、プロジェクタのガンマは無関係でした。しかし正弦波を投影する場合、**プロジェクタのガンマ補正（通常 2.2 程度）が正弦波の形を歪め、周期的な位相誤差（波打ち）として結果に現れます。**

カメラ側のガンマは 1.0 に固定済みですが、プロジェクタ側は未知です。

対処は 3 つあります。

1. **位相シフトの枚数を増やす**（N ≥ 5）。主要な高調波成分が打ち消され、誤差が小さくなります。N = 8 なら実用上かなり抑えられます
2. **プロジェクタのガンマを実測して逆補正をかける**。階調パターンを投影・撮影して応答曲線を作ります
3. **プロジェクタ側の設定でガンマを線形に近づける**（機種によります）

**まず N = 8 で試し、残差画像に周期的な縞が見えたら 2 に進む**という順序を推奨します。[reconstruction.md](reconstruction.md) の 5.4「残差の画像」が、まさにこれを見つけるための道具です。縞の周期が位相の周期（16 投影画素）と一致していれば、ガンマが原因と判断できます。

### 飽和

正弦波の山の部分が飽和すると、位相が系統的にずれます。二値パターンより飽和に敏感です。**露光は現在の 5000 µs から見直す必要があるかもしれません。**

### 位相接続の失敗

グレイコードの誤差が T/2 を超えると、隣の周期に飛びます。症状は「一部の領域だけ T 画素分ずれる」という段差で、点群では平面に段差として現れます。T を大きくするか、`skip_fine_bits` を下げて（＝グレイコードの分解能を上げて）対処します。
